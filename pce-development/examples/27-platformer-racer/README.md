# 27 — Platformer + racing scene handoff (HuCard)

This **executable two-phase game skeleton** demonstrates safe rules for a Contra-like game that alternates between a side-scrolling platformer and a top-down racing segment. It does **not** claim to be a finished Contra clone or a full perspective Mode 7 racer. `main.c` and the generated `hybrid_rules.h` implement both scenes; there is no PSG initialization and no debugging text generated by the engine.

Controls: in the platformer, LEFT/RIGHT walks and a newly pressed I jumps. On reaching platformer world X=440, the scene changes. The racing stage loads its own 16-colour road BAT and reinterprets LEFT/RIGHT as **lane X**, while UP advances **forward Y**; jumping/gravity are inactive. When forward progress reaches 480 pixels, the platformer scene and sprite patterns reload, then the player respawns at X=32. Both state transitions reset stale camera and control state.

The original road BAT/patterns are generated **offline** by `tools/build_race_art.py`. They are used only for the phase-change teaching demo, not as a substitute for the correct 512×224 paired-BAT pseudo-bitmap Mode 7 renderer in [`../micro/86-mode7-bitmap-floor`](../micro/86-mode7-bitmap-floor/README.md).

```sh
make                   # LLVM-MOS HuCard
make rules-check        # reject invalid game JSON
make assets             # regenerate the race background (requires Pillow)
make simulate           # host-only Q8 oracle from tools/hybrid-scenario.json
make run                # neutral pad emulator screenshot
make hybrid-test        # scripted emulator scene transitions if RPC input is available
make trace              # P2TR platformer scenario if RPC trace_frames is available
```

The JSON file `tools/hybrid.json` is the source for movement rates, trigger distances, and lane limits. `tools/offline.py generate` deterministically builds `src/hybrid_rules.h`; every compile depends on it. That generator validates bounds and deliberately rejects 3+ stages: to add more stages, extend the code and tests together.

Debug using `hybrid_scene` (0 platform, 1 race), `hybrid_race_lane_q8`, `hybrid_race_progress_q8`, and the platformer `pce_platformer_trace`. P2TR scene 4 is used for the racing phase, excluded from platformer-only collision checks. Never infer collision behavior from the static scene screenshot or host-only oracle. No title state, enemy AI, shooting, fade transitions, save/load, SuperGrafx or disc packaging is implemented; these are explicit extension tasks, not hidden features.
